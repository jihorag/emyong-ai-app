# 주석 — 쓰지 않습니다

## 규칙

> **코드에 주석을 달지 않습니다.**
>
> 무엇을 하는지는 코드가 말합니다. 이름을 고치거나 함수를 쪼개서 드러내세요.

**ESLint가 강제합니다.** `local/no-comments` 가 주석을 에러로 잡습니다.

```
✗  // 사용자 목록을 가져온다
   const d = await f();

✓  const users = await fetchUsers();
```

## 예외는 둘뿐입니다

**1. `⚠` 로 시작하는 경고**

고치면 조용히 깨지는 자리. 코드로는 표현할 수 없는 것만.

```js
// ⚠ 탭 이름으로 판정하면 안 된다. AI 대화와 변형문제가 같은 탭 안에 있어
//   구분이 안 되고 기록이 0이 된다.
```

경고에 해당하는 것:

| | 예 |
|---|---|
| 바꾸면 회귀가 나는 문자열 | 프롬프트 4종 — 한 글자만 달라져도 `npm run verify` 실패 |
| 데이터 계약 | localStorage 키 구조 · 학습시간 버킷 이름 |
| 과거에 실제로 났던 버그 | 단원 ID를 dataModel 밖에서 만들어 교집합이 0/97이 됐던 일 |
| 팀 합의가 필요한 것 | 공용 파일 · 9색 팔레트 |
| 순서 의존 | 인사·개관을 먼저 깔고 카드 생성은 뒤에서 |

**2. eslint 지시어**

`eslint-disable-next-line` 등은 문법이지 설명이 아닙니다.

## 앱 밖은 예외입니다

`test/` · `scripts/` 는 규칙이 꺼져 있습니다. 콘텐츠 출처와 실행 순서를
적어 둬야 나중에 다시 돌릴 수 있습니다.

## 왜

주석은 코드와 함께 낡습니다. 코드를 고치고 주석을 안 고치면 남는 것은
**틀린 설명**이고, 그건 없는 것보다 나쁩니다. 읽는 사람이 코드와 주석 중
무엇을 믿을지 판단해야 하니까요.

한때 이 저장소에 주석이 684줄 있었습니다. 대부분 코드를 한 번 더 옮겨
적은 것이었고, 일부는 이미 사실과 달랐습니다. 26줄만 남겼습니다.
