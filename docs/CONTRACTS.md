# 계약 — 프론트와 백엔드가 만나는 두 지점

폴더를 나눠도 두 사람이 반드시 합의해야 하는 경계가 있습니다. **딱 두 개입니다.**
이 둘만 고정하면 나머지는 서로의 폴더를 안 봐도 됩니다.

> 여기 있는 형식을 바꾸려면 **양쪽 담당이 함께 승인**해야 합니다.
> 한쪽만 바꾸면 반대편이 조용히 깨집니다 — 빌드는 통과하고 화면만 이상해집니다.

## 계약 1 — Unit 타입

`src/data/dataModel.js`가 조립해서 내보내는 단원 객체입니다.
**화면은 이 모양만 알면 되고, 데이터 파일이 어떻게 생겼는지는 몰라도 됩니다.**

```js
Unit = {
  id:         'math__edu__00',        // ★ 진척 기록의 키. 절대 바꾸지 말 것 (아래 경고)
  subject:    'math',                 // 과목 id (영문)
  area:       '수학교육론',            // 영역명
  title:      '베르트하이머',           // 단원명
  path:       ['수학', '수학교육론', '베르트하이머'],   // [과목, 영역, 단원]
  study_file: '수학교육론_….md',      // 단권화 노트 파일명 (없으면 null)
  cloze:      [ClozeCard],            // 빈칸 카드
  practice:   [PracticeItem],         // 기출·변형 문항
}

SubjectModel = {
  subjectId, title,
  areas: [{ name, group, no, units: [Unit] }],
  stats: { units, cloze, practice, withStudy },
}
```

### 화면이 이 타입에 의존하는 방식

| 쓰는 곳 | 무엇을 |
|---|---|
| `screens/review` · `screens/variant` | `areas` → 목차 아코디언, `unit.cloze`/`study_file` → 복습 모드 가용 여부 |
| `screens/home` | `unit.id`로 mastery 조회, `unit.path.slice(1)`로 취약단원 이름 |
| `app/App.jsx` | 전 과목 프리로드 |

### ⚠️ `unit.id`는 진척 데이터의 기본 키입니다

`ailearn-mastery`, `ailearn-drill:{id}`가 전부 이 값을 키로 씁니다.
바꾸면 **이미 앱을 쓰고 있는 사용자의 학습 기록이 전부 사라집니다.**

과거에 실제로 사고가 났습니다 — 화면이 자체적으로 단원 ID를 파생하는 코드를 따로 갖고 있어서,
기록하는 키와 읽는 키가 어긋났습니다(361단원 교집합 0). 아무리 복습해도 대시보드가 0이었습니다.

**규칙: 단원 ID를 만드는 곳은 `dataModel.js` 하나뿐입니다.** 어디서도 새로 파생하지 마세요.

## 계약 2 — AI 응답 포맷

프롬프트(`src/prompts/`, 백엔드)가 모델에게 **이 형식으로 답하라**고 지시하고,
렌더러(`src/components/ParsedText.jsx`, 프론트)가 **그 형식을 파싱**합니다.
둘이 짝입니다.

### ① 서답형 문항 — ` ```exam ` 펜스

```
```exam
[5점]
다음은 …이다. 밑줄 친 __㉠__에 대해 서술하시오.

〈자료〉
김 교사: "…"
박 교사: "…"
```
```

| 요소 | 의미 | 파서 |
|---|---|---|
| 첫 줄 `[N점]` | 배점 배지 | `components/ExamCard.jsx` |
| `__…__` | 밑줄 강조 | ExamCard |
| `〈자료〉` / `〈보기〉` | 제시문 블록 시작 | ExamCard |
| `화자: 발화` | 대화 행 | ExamCard |

지시하는 곳: `prompts/variant.js`

### ② 암기 카드 — `Q :: A`

스제트 카드 생성 응답. 한 줄에 카드 하나.

```
브루너의 표상 3단계를 순서대로 :: 행동적 → 영상적 → 상징적
```

파서는 `::` 외에 `｜`·`|`도 받고, 앞의 번호(`1.` `1)`)는 무시합니다.

### ③ 드릴 채점 — 첫 글자가 `O` 또는 `X`

```
O 정답! 관계적 이해 / 도구적 이해
X 정답: 통찰 — 부분의 관계를 재구성하는 것
```

**첫 글자로 정오를 판정**합니다. 형식이 깨지면 문자열 포함 여부로 폴백하지만 정확도가 떨어집니다.

### ④ 도표 — ` ```viz ` / ` ```mermaid ` / ` ```svg `

`components/viz/`가 처리합니다. `svg`는 `SafeSvg`가 `<script>`·`on*`·`<iframe>`을 제거한 뒤 렌더합니다.

## 이 계약을 지키는 장치

`npm run verify`가 매번 확인합니다.

- **프롬프트 바이트 대조** — 5종 20,405자. 한 글자만 달라져도 실패합니다.
  구조를 옮기는 작업에서는 절대 안 바뀌어야 합니다.
- **localStorage 키 스냅샷** — 키가 사라지거나 새로 생기면 실패합니다.
- **화면 렌더 14곳** — 파싱이 깨지면 해당 화면이 안 뜹니다.

기준선(`viewer/test/baseline/`)은 **의도적으로 형식을 바꿨을 때만** 갱신합니다.
갱신했다면 커밋 메시지에 무엇을 왜 바꿨는지 쓰고, 양쪽 담당이 리뷰합니다.
